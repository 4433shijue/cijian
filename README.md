# 此间 · 角色小剧场

当前版本：**2.3.0**

这一版让小剧场可以参与。论坛支持筛选、楼中楼和观众回帖，身体状态卡支持角色、部位切换，栏目和单项可以主动追加。默认清晰阅读与可调字号同时适用于旧 HTML。八种内置预设各有内容丰富度要求，由应用渲染可信结构，AI 负责内容和受控主题；展开才加载，收起即卸载。小剧场及用户回帖独立保存，不进入正式剧情记忆。继续保留角色卡补全、20回原文窗口、段落记忆和分块备份迁移。

由你决定剧情进度的本地优先网页。小说只扩写指定瞬间；手机聊天与正文共享故事经历，按角色知情范围读取资料。

## 打开使用

Windows 双击根目录 `start.bat`，打开终端提示的 http://127.0.0.1:4173 。保持终端打开。

1. 第一次进入，在首页点击「带我开始」。依次完成连接模型、创建角色、开启故事、写出第一段。也可以暂时收起，从「继续新手引导」返回。
2. 连接页填写 URL、API Key，点击「尝试获取模型列表」，再从「模型名」下拉框选择；也可以手动填写模型名。选好后点击「测试连接并继续」。其他协议在「高级设置」选择。角色只需名字和人设，世界书与开场背景均可稍后补充；已有角色、故事和验证过的连接可以复用。
3. 正文输入动作和台词，点击「扩写这一刻」。正文输入框中的「写作偏好」可以选择文风预设、篇幅和心理描写；完成正文后还可以用「仅换文风」生成只改变表达方式的候选版本。手机聊天选择自己的身份与对象，可连续点击「发送消息」，说完后点「让 TA 回复」。
4. 新故事默认自动互通，普通正文直接进入聊天参考，聊天也会带回正文。旧故事点一次「整本启用自动互通」即可迁移，已有的特定角色授权和曾撤回的授权会保留。段落「编辑」可设为「私密段落 · 仅作者可见」，或「仅共享下方授权的事实」。作者开场背景、他人的私密人设和未参与的私聊仍会过滤。
5. 「记忆中心」自动保存有省略的原文摘记，可编辑或忽略，不需要逐条接受，也不额外调用模型。可选的「AI 整理摘要」按批次提炼旧经历，结果在自动互通模式下直接生效。故事设置保留「严格知情（高级）」，该模式继续使用授权事实与人工确认的候选记忆。
6. 定期在设置导出完整备份。换设备后导入副本，并重新填写 Key。

新手引导会暂存当前步骤、角色人设和故事表单。它不会把密钥写进引导草稿；没有勾选「记住此设备的 Key」时，刷新后需要重新填写密钥。完成第一段正文并成功保存，才会标记引导完成。手机聊天、故事记忆的使用说明会在进入相应功能时出现，并可以收起。

普通连接管理仍在「设置 → 添加接口」。已创建的故事可以在「故事设置 → 带入另一位角色」中添加角色库中的角色。故事页工具栏的「故事状态」会汇总未完成草稿、待复核内容、失效记忆和模型连接问题。

API 设置的「生成偏好」可调整温度，留空使用模型默认值。Chat、Responses、Gemini 可填写 0 到 2，Claude 为 0 到 1；部分模型只接受默认温度。重复惩罚默认设为最高可选值，Chat 为 2，Gemini 按两位小数精度设为 1.99（避开 2 的边界），Claude 和 Responses 不发送此参数。可调低或清空重复惩罚以使用模型默认值。旧接口配置也会应用新的重复惩罚默认值；手动调整按接口保存，并随备份导出和恢复，正文、聊天、灵感小助手及记忆整理都会使用当前接口的设置。模型拒绝这些参数时会提示修改，不会自动重试。

参数依据 [OpenAI Docs · Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Responses](https://developers.openai.com/api/reference/python/resources/responses/methods/create)、[Claude Messages](https://platform.claude.com/docs/en/api/messages/create)、[Gemini GenerationConfig](https://ai.google.dev/api/generate-content#v1beta.GenerationConfig) 与 [Google 生成参数范围](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/model-reference/inference)。兼容服务最终支持哪些参数，以服务和所选模型为准。

「角色 → 添加角色」会随输入自动保存草稿，包括名字、简介、完整人设、头像和逐段设置。关闭窗口、切换页面或刷新后，再次点击「添加角色」即可接着填写。只有点击「保存角色」并保存成功才会清除草稿，下次创建会打开空白表单；保存失败会保留草稿。草稿留在当前浏览器，不会出现在角色库中；1.7 起会随完整备份导出。导入时如本机已有角色草稿，会保留本机草稿，并将导入草稿另存进角色库，在名字中标注「导入草稿」。

### 从素材补全角色卡

在角色页点击「帮我补全」，输入人设、故事、对白或零散想法，选择单人或多人。可以提前指定主角、补充创作要求，并选择「忠于原文」「适度补全」（默认）或「自由丰富」。使用设置中当前选中的模型接口。

单人明确时直接生成；人物有歧义或多人未指定时，先确认候选名单，可以修改称呼、添加遗漏人物、排除配角。每张卡包括基础身份、外貌与表现、成长与经历、性格层次、欲望与底线、能力与生活、说话与互动、人际关系、秘密与知情范围、当前状态。预览区区分原文已有、推测、新增及待补充内容；引用可与素材核对，但模型的理解和补充仍需作者复核。

多人逐张生成，完成的卡会保留，失败后可继续或重试指定人物。可以修改名字、公开简介及各维度，勾选保存或全部保存到角色库。生成结果采用前不会进入角色库或故事；保存的人设段落默认不向其他角色公开，公开简介请先确认。保存不会自动改写已经建立的故事副本。

补全素材、候选名单和结果自动暂存在当前浏览器，关闭窗口或刷新后可以继续；中断不会自动重新请求。补全工作区与手动创建角色的草稿独立，替换导入备份时也会保留本机的补全工作区。尚未采用的补全工作区不包含在资料备份中；需要迁移的卡请先保存到角色库，再导出备份。完整人设继续按原有上下文规则读取，超过模型容量时提示调整，不静默截断。

新正文成功保存或新草稿确认采用后，会自动折叠较早的已完成正文，最新一段保持展开。生成失败不会改变旧段落的折叠状态；重写只展开重写的目标，不折叠其他段落。仍可用「展开本段」「折叠本段」手动调整，状态随故事保存，不影响版本、记忆或模型参考原文。

故事右下角的两个箭头可一键回到顶部或底部。输入框和功能栏都支持单独收起，手机端也可以使用；未发送内容会保留，同一浏览器标签页刷新后继续保留收起状态。点击「沉浸阅读」会隐藏导航、功能栏、输入框和段落操作，并临时展开全部正文；点击「退出阅读」或按 Esc 恢复原先的界面与段落折叠状态。生成过程中收起输入框或进入沉浸阅读，仍可点击「停止生成」。

台词用字差异默认不检查。开发者模式的「台词检查（只提醒，不拦截）」可显示差异提醒，完整正文照常保存。辅助 facts 格式有误时只跳过摘录，不阻止正文入库。输出正文格式异常或生成中断仍保留草稿，可通过「检查并采用」编辑后确认；采用不调用 AI。重写和恢复保留旧版本，原文后来改过时阻止覆盖。只修改事实授权或单段可见性不会标记全部后文；实际修改正文会留下提醒，自动互通模式仍继续参考当前保存的后文，并更新受影响的摘记。

正文与聊天合计最多读取20回有效原文。一段已采用正文是一回，一次「让 TA 回复」的整组消息也是一回。窗口超过20回后一次移走最早5回，形成16～20回滚动；删除后不回填窗口外原文。每回有稳定编号，重写保留原编号，只采用当前版本；未采用草稿、已删除内容和被替换的旧稿不进入上下文。关键词不再召回窗口外原文，旧版自动摘记只保留供查看。重写历史回合只读取其之前的有效经历和记忆。固定设定、所选记忆与窗口原文均为必读，超过配置容量时发送前提示，不静默截断。

「设置 → 开发者模式」可设置每几回合自动提炼记忆（默认5回）和最多自动读取几条（默认8条，0表示不自动选择）。每批生成一段连贯的小结，标题标明来源回合；不同知情范围分别整理。近期原文已经覆盖的记忆不重复自动带入；更早记忆按来源先后排列，优先选择最近的有效内容。记忆库不设置总字数上限，但模型请求仍受配置容量约束。

「故事记忆」显示下次会带入的勾选结果，可临时增加或减少。临时选择只用于下一次成功并采用的正文或聊天回复，之后恢复默认；预览、灵感与记忆整理不消耗选择，失败和取消会保留。灵感使用默认记忆数量，不使用一次性选择。来源版本变化后旧记忆立即暂停使用，并按当前来源重新提炼；不能直接确认旧记忆并重新绑定新版本。

已有故事不会在升级后自动调用模型整理全部历史。「一键补齐回合记忆」显示范围、批数和预计请求数，点击一次后按批串行整理，可停止、刷新后继续或失败重试，完成批次会保留。新回合按设置自动提炼；失败时提示缺失范围，写作可以继续。自动记忆开关在故事记忆中心，整理会使用当前模型接口并产生请求。

API 高级设置的「多轮前缀复用」默认对 DeepSeek 官方 Chat 接口或模型名含 deepseek 的兼容接口启用；中转站使用其他别名时可手动开启。窗口内保留成功请求与原始回复，新内容追加在末尾，不额外调用模型预热。正文、聊天对象和接口分别保存请求，但都遵守同一故事的回合窗口。窗口滚动、修改历史或知情范围、变更所选记忆时重建请求；一次性选择恢复默认后，额外记忆也退出缓存。没有选中的新记忆不会打断缓存。

固定规则、世界书和人设放在前面，随后为所选回合记忆、窗口原文与当前输入。缓存只复用符合当前窗口、版本和选择的内容，不会继续保留窗口外原文；接近配置容量时可提前重新整理。旧版缓存首次使用新机制时重新构建。删除故事时同时删除缓存，缓存不随备份导出。

开发者模式的「参考内容」显示服务返回的缓存命中、未命中、命中率与耗时，同时显示实际原文回合范围、所选记忆数、缺失记忆范围、设定/记忆/原文的本地用量估算，以及延续或重新整理前缀的原因。DeepSeek 的命中率按 `prompt_cache_hit_tokens / (prompt_cache_hit_tokens + prompt_cache_miss_tokens)` 计算，未命中不当作缓存写入；官方流式请求会要求返回 usage。其他接口缺少统计时显示「服务未返回」，不把未知显示成零。最终请求可查看实际发送的 messages。DeepSeek 的缓存自动开启，完整相同前缀有助于复用，但建立需要时间，也会过期或被清理，不能保证命中。参考 [DeepSeek 上下文硬盘缓存](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/) 与 [多轮对话](https://api-docs.deepseek.com/zh-cn/guides/multi_round_chat/)。

输出格式仍可选择自动、严格结构、JSON 或兼容模式。其他协议原有缓存参数保持不变：Claude 使用固定材料末尾的短期缓存标记，已识别的官方 GPT-5.6 Responses 使用显式缓存边界，可在高级设置关闭显式标记。服务自身的自动缓存由服务管理；接口拒绝参数时提示调整，不自动重试。参考 [OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)、[Claude Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、[Gemini Caching](https://ai.google.dev/gemini-api/docs/generate-content/caching)。

卡壳时点击正文输入框旁的「灵感小助手」。它使用当前故事的人物副本、适用世界书、20回窗口内最近3段完整正文与聊天，以及尚待回复的已发送消息。默认记忆数量与开发者设置一致，优先补充所选原文没有覆盖的较早经历；不读取旧自动摘记，也不使用或消耗下一次回复的临时勾选。记忆来源必须仍对应当前有效版本。严格知情模式排除待复核经历，材料标明人物知情范围；开场背景、未采用输入和旧候选不当作当前共同经历。

小助手仍提供四个候选，但不再强制凑齐关系变化、信息发现、外部变化与主动选择。建议可以留在同一场景，允许迟疑、拒绝、沉默或维持现状；态度变化需要前文依据。JSON 只检查卡片是否完整，不做类别、措辞或人物行为的机械拦截，也不增加第二次模型审查。具体建议质量仍受所选模型影响。

选择只会把建议放进输入框，已有文字会保留，可以调整后再扩写。可在「这次希望怎么调整？（可选）」写下反馈，再点「你再想想」生成新一轮。有效的一轮建议按故事保存，重开或刷新不会重新请求。正文、人设、世界书、聊天、记忆、知情设置或作者想法改变后，旧候选保留供查看并提示更新，重新生成由用户点击触发；生成期间参考内容变化时，迟到结果也不会覆盖当前建议。旧版本保存的候选需要手动更新一次。下一段正文、正文重写或草稿采用成功后仍清空旧建议；折叠、阅读模式与书名等显示变化不使建议过期。

在「设置 → 开发者模式」可以编辑六类内部提示词、调整记忆频率、读取数量和灵感参考段数，并在「文风预设」中复制内置风格、创建自己的预设。预设只描述语言风格，剧情边界、输出格式和知情过滤仍由程序固定维护。关闭开发者模式后已保存的预设与提示词仍然生效。建议属于作者尚未采用的设想，不会自动成为正文、事实或故事记忆，也不随备份导出。素材超过模型容量时会提示调整，不会悄悄省去指定的正文与设定。

数据跟随浏览器和网址端口。开发端口 5173、预览端口 4173、GitHub Pages 属于不同存储位置，请用备份迁移。隐私窗口关闭、清理网站数据可能移除存档。API Key 默认不跨页面刷新保留；选择记住此设备才会保存，导出始终排除密钥。浏览器直连接口需要服务支持 CORS。

## 段落小剧场

每次生成的一整块正文底部都有「小剧场」。首次点击会展开并请求当前接口，参考本书人物设定、适用世界书和这一回合的当前正文；不带其他回合、聊天、记忆或开场背景。已生成的内容再次展开时直接读取本机记录，不重复调用 AI。

故事设置中的「每段正文自动生成小剧场」默认关闭。开启后，小剧场要求并入正文同一次请求，按 text、facts、theater 返回正文、辅助摘录和结构化栏目；不追加第二次请求。自动结果默认折叠，展开时逐个显示已经完整接收的栏目。正文与小剧场共用接口输出限额，优先完成正文。整次回复中断、停止或达到上限时，正文仍保留为草稿，需要检查采用；正常结束且正文有效但小剧场缺失或格式有误时，保存正文并提示单独重试。仍兼容旧接口返回的 theaterHtml。

故事设置中的「小剧场丰富度」控制番外展开程度。轻量抓住一两个重点，标准会补充具体细节和一轮回应，丰富会展开多个短小层次。新故事默认标准，旧故事缺少这个字段时也按标准处理。它只影响下一次生成，已经保存的小剧场保留生成当时的密度快照。

开发者模式提供「主角们的吐槽」「没被发现的细节」「话外之音」「来自第四面墙的观众」「角色的身体变化」「关系里的小变化」「场景里的声与光」「物件与线索」八种内置预设。可以修改、恢复、复制、新增与排序，默认仍选主角吐槽。提示词按 human-writing 的人物口气、具体动作与自然中文要求润色。丰富度按栏目分别展开，论坛增加不同观众与回复分支，身体卡细分与动作相关的部位，话外音保留不同理解；材料不足时不强行填满数量。身体目录可覆盖20余处部位和非人结构，正文未提及的项目单独折叠，不能当作正常状态；前后变化仅指本回合，不凭空继承其他回合的伤势或感受。

内置栏目使用经过校验的楼层、条目与回复关系，由应用渲染为卡片。文字与底色由应用成套控制，可选纸色、森林和夜色主题；默认开启「清晰阅读」，字号16～24。旧 HTML 和自定义 HTML 仍经 DOMPurify 清理后置于禁用脚本、外部资源、表单与跳转的 iframe，清晰阅读会修正难以辨认的样式，不需重新生成。收起后卸载结构化界面、iframe 和观察器，重新展开不请求模型。

论坛可只看楼主、追踪观众、隐藏猜测、展开多层回复；身体卡可以切换角色、分组、部位及只看有变化的项目。赞、收藏、筛选、字号和展开均在本地完成。点击「查看正文依据」时核对当前正文中的逐字引用，匹配失败会明确提示待核对；引用匹配不代表模型推测已被证实。

在论坛写一句话，点击「发送并生成回复」才会调用 AI 追加回复。也可点击「细写此项 · AI」「追加本栏 · AI」或指定补充方向。追加只参考这本故事的设定、适用世界书、目标正文与当前栏目已有讨论，不带其他栏目、其他回合、聊天或记忆，不擅自提高输出额度。留言草稿、已发送留言、原始响应和失败状态留在本机，失败重试不会重复插入同一句留言。停止、刷新不会自动补发；已有结果始终保留。生成时正文、人设、世界书或所绑定的小剧场发生变化，迟到结果不能覆盖新版。旧 HTML 可清晰阅读；重新生成结构化结果后才提供这些交互。

小剧场绑定正文版本。正文编辑或重写后会提示原文已更新，旧结果可查看，新结果由用户生成或随开启的自动模式生成。内容不进入正文、事实摘录、人物知情或回合记忆。自动小剧场回复也不作为原始 assistant 消息继续复用，后续按正式正文重新组装历史；固定设定前缀仍保留，服务实际缓存命中以返回统计为准。

小剧场原始响应独立保存在本机，需要时可打开「查看模型原始输出」，不会随正文列表反复加载。刷新后未完成任务标记中断，不会自动重发。小剧场会随完整备份和单本备份保存；作品导出勾选「附上小剧场」后，仅附当前正文版本最近成功生成的内容。导出使用栏目名称与纯文本，Word、EPUB 和打印预览采用简单边框排版，不执行或原样嵌入 AI 代码。

## 作品导出与备份迁移

在「故事设置 → 导出作品」选择纯正文、正文与聊天或仅聊天，按所选内容的先后顺序导出全部或起止范围（包含两端）。作品只取当前已完成且未删除的版本，可附上开场背景和人物的名字、简介，不附带完整私密人设。提供 TXT、Markdown、真正的 DOCX 与 EPUB 文件；DOCX、EPUB 可设字号、行距和正文段落另起一页。PDF 使用「打开打印预览」，可继续调整排版，再在浏览器打印窗口选择「另存为 PDF」；弹窗被拦截时可点击生成后的预览链接，或保存 HTML 排版文件。排版与分页受阅读器、字体和打印设置影响。

「备份这本故事」包含该故事的人物副本、关联角色、适用世界书、正文与聊天的全部版本、已删除内容、记忆、聊天回复批次、文风与输入草稿；共享世界书在副本中限定为这本故事，不影响已有故事。单本备份不带其他故事、接口配置、全局提示词或未采用的灵感候选。在「设置 → 保存与迁移」仍可导出完整资料，额外保留全局设置与创建角色的草稿。备份保留稳定回合编号、窗口起点和记忆来源，兼容旧版记录；所有备份均排除接口 Key、请求报告、上下文复用缓存和一次性记忆选择。

新备份使用 `little-scene / version: 3`，兼容导入 `version: 1` 和 `version: 2`。新备份包含结构化栏目、观众留言及草稿、追加状态、赞与收藏、阅读设置。旧应用会拒绝新备份，避免静默丢失交互；旧 HTML 结果原样保留。后台 Worker 每次读取最多 1 MiB 字节，跨块解码 UTF-8，逐条解析并分批写入 IndexedDB 临时区，不会把所有分块拼成一整份 JSON 后再解析。单条资料（一个角色、一段正文及其所有版本等）最多约 1600 万 UTF-16 码元，超出时停止并保留原资料；文件总量仍受设备可用存储限制。不要将分块处理理解为无限容量。

预览展示故事、角色、正文聊天、记忆、世界书和角色草稿数量。默认新增副本并保留本机模型、Key 与提示词；勾选「应用备份中的模型配置、提示词及偏好设置」后才应用这些备份设置，导入的接口需要重新填写 Key。故事使用的 DIY 文风与小剧场预设始终带入，冲突版本另存，不覆盖本机预设。完整备份也可在确认后替换故事资料；单本备份只允许合并。

所有关系检查成功后，分批写入在一个数据库事务内提交。取消、格式错误、存储空间不足或提交中断会回滚，已有资料不出现半本导入结果。支持 Web Locks 的浏览器在重新打开时清理无人使用的临时区；不支持的旧浏览器保留最近临时区以避免误删另一标签页的任务，24 小时后清理。备份和作品导出同样逐条读取，在一致的数据库快照中把输出分成 Blob 页暂存，不同时拼接整库文本。临时区会额外占用浏览器存储，最终保存期间其他资料写入可能短暂等待。

v1.7 用包含 1200 条经历、长中文人设与大头像的约 118 MB 备份完成了桌面 Chromium 导入、导出与页面响应测试，也验证了取消、提交时强制终止 Worker、刷新恢复、重复 ID、错误关联和模拟配额失败。移动端验证使用浏览器视口，未据此保证所有真实手机的容量或速度。

## 手机聊天的连续消息

「发送消息」只保存本机气泡，不调用模型，未配置接口也可以先写。待回复消息按故事和双方身份分别保存，刷新后仍在。「让 TA 回复（N）」只发送已点过发送的 N 条消息；输入框中尚未发送的文字仍作为草稿保留。

开始生成时固定本组消息；期间继续发送的消息留到下一轮。AI 先理解整组内容与后文纠正，再按语境返回独立气泡。一次请求返回 `{"messages":["第一条","第二条"]}`，通过完整性与结构校验后一次保存，接收期间显示「对方正在输入…」。手机端两种发送操作并排显示，新消息自动滚入可见区域。

失败、停止或刷新中断时，已发送消息不重复插入，收到的原始内容保留在「查看模型原始输出」。可以「重试本组」，或「返回待回复」后与补充消息重新组合。已有回复使用「重新生成本组」，整组替换并保留旧版本；生成失败可保留原回复。生成期间来源或原回复被修改时拒绝覆盖。

备份包含待回复状态、回复批次和关联，导入时重新映射 ID；旧版备份仍可读取，旧聊天不会自动重新发送，首次重新生成时会识别相邻的同组回复。

## 开发与构建

需要 Node.js 24。Windows 启动脚本使用 PATH 中的 Node，也支持用 `SCENE_NODE_PATH` 指定安装目录；项目旁的 `toolchains/node-v24.18.1-win-x64` 存在时会优先使用。

```sh
npm ci
npm run dev
npm test
npx playwright install chromium
npm run test:e2e
npm run build
npm run preview
```

生产文件在 `dist/`，必须通过静态 HTTP 服务访问，不能用文件协议双击 HTML。UI 使用本地水彩贴图，无运行时远程字体或图片依赖。浏览器测试默认使用 Playwright 安装的 Chromium，也可用环境变量 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定 Chrome 路径。

## GitHub Pages 准备

将审核后的源代码放入选定的仓库，默认分支 main，在仓库 Settings → Pages 选择 GitHub Actions。已提供 `.github/workflows/pages.yml`，设置仓库子路径、运行测试、构建并部署 `dist/`。页面使用 hash 导航，直接刷新故事地址不会请求服务器上的虚构子目录。用户站点仓库（`用户名.github.io`）或自定义根域名请将 `VITE_BASE_PATH` 改为 `/`。

网页供每位访客填写自己的模型接口和 API Key，使用各自的额度。Pages 只托管网页文件，不提供模型代理；接口必须支持 HTTPS，并允许来自站点域名的 CORS 请求。不要把供所有人共用的密钥写进源码、构建变量或 GitHub Actions：浏览器能收到的密钥也能被访客读取。

发布前运行 `npm run prepare:release`，在 `work/github-release/<时间>/source/` 得到按明确文件清单整理的源码副本和对应的核验清单。仅发布审核过的源码副本；`outputs/`、`work/`、备份、日志和环境变量不会被复制。脚本检查常见凭据格式和当前环境中的已知密钥，但不能代替人工审阅。正式部署内容由 Actions 重新构建产生。不要直接上传整个工作目录。已有仓库还需要检查 Git 历史，忽略规则不会撤回已经提交的资料。

角色、聊天和剧情不会随代码发布自动上传，但导出的备份包含这些完整内容。仓库内测试角色为虚构角色，API Key 不进入打包配置。具体存储和传输边界见 [数据与隐私说明](PRIVACY.md)。

## 实现结构

- `src/db.ts`：Dexie 数据库、故事角色副本、版本与记忆失效。
- `src/model.ts`：四协议、SSE 分片、取消、超时和完成标记。
- `src/rounds.ts`：统一回合编号、20回窗口和有效记忆选择。
- `src/round-memory.ts`：段落提炼、按权限分批、失败恢复与旧故事补齐。
- `src/context.ts`：知情过滤、固定前缀、预算和实际参考报告。
- `src/prefix-cache.ts`：多轮请求复用、历史与知情范围变更失效、容量重整和命中率计算。
- `src/style-presets.ts`：内置文风、开发者自定义预设与故事文风解析。
- `src/output.ts`：结构约束、JSON 提取、可读草稿恢复与台词检查。
- `src/engine.ts`：故事互斥任务、草稿、事实摘录和记忆进度。
- `src/prompts.ts`：固定边界与 human-writing 润色后的可编辑提示词。
- `src/backup.ts`：备份记录格式与兼容校验。
- `src/backup-parser.ts`、`src/backup-transfer.ts`：增量解析、暂存校验与原子导入。
- `src/transfer.worker.ts`、`src/transfer-store.ts`：后台执行、快照导出与临时存储清理。
- `src/work-export.ts`、`src/TransferPanels.tsx`：作品文件、打印排版与导入导出界面。
- `src/Onboarding.tsx`、`src/onboarding-state.ts`：四步引导、草稿恢复、首次生成完成判断及按场景出现的提示。
- `src/ConnectionForm.tsx`：引导与设置共用的连接表单、验证、取消与错误提示。
- `src/assets/onboarding/`：从项目已有水彩素材裁切的五张 WebP 贴图；可用 `scripts/prepare-onboarding-art.py` 重新生成。

“不续写”和保留台词原意由固定提示词约束，程序无法机械证明模型没有添加隐含剧情。可选台词检查只比较文字并给出提醒，不裁定语义对错。正文可修改、重写或恢复版本。token 数为本地估算，不等于服务的实际分词；服务返回用量时会单独显示。
